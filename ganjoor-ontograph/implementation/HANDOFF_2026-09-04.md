## 1. Project introduction (for a fresh reader)

**Ganjoor Ontograph** is a command-line research apparatus for OOO-informed
close/distant reading over the Ganjoor Persian poetry corpus (132,538 poems,
vendored read-only in the parent repo). It is Mohammad Zare's applied
instantiation of his broader **Ontograph** architecture (registered in
mozare-wiki: relation-before-type, profile/permission/event/residue records).

**Core epistemic discipline** (never violate these):
- An Anchor Hit is never an object occurrence.
- Co-incidence is never a Relation-Object.
- An estimate is never a census; a proposal is never evidence.
- Ambiguity stays visible in counts and denominators.
- A renderer never computes research results.
- Agents propose (candidate-tier); humans decide.

**Governed research chain** (the Amendment's central design):
```
verbatim hunch → attributed proposals → corpus verification + lexical-neighbor
proposals → EXPLICIT HUMAN REVIEW → provisional Object Address + approved
anchor → stable Anchor Hits + per-hit walk → complete assessed operation →
descriptive co-incidence catalog → self-contained release
```

**Why the inquiry layer exists:** the researcher's Rostam test
(session 20260901_193123, "cluster Rostam's battle strategies") produced a
17-episode × 15-label dataset that BYPASSED the apparatus — labels were agent
judgment, no situations, no per-hit assessment, no census. His verdict: the
walk-in process was absent; the machine must guide toward ontography (object
listing, cataloging, relation mapping) using what it can check precisely.
The 2026-09-02 Amendment to the V0.2 execution spec (written by Codex
gpt-5.6-sol high, reviewed and accepted) re-sequenced the plan around this.

**Key files:**
