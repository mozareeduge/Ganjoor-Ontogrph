# Terminology (project-local; see spec §5, Part II)

Do not use these words loosely. Each names a distinct record with a distinct
authority. Full schemas are in the spec, Part VIII.

- **Seed** — the initiating object/cluster as first conceived, plus reason and uncertainty. Not yet an Object Address.
- **Object Address** — provisional persistent identity for something the study returns to. Can split/merge.
- **Lexical Anchor** — a textual form used to locate candidate passages. Not the object.
- **Anchor Hit** — the deterministic fact that an approved anchor matched a source span. Not an object occurrence.
- **Occurrence Assessment** — whether a hit counts as an occurrence of the Object Address: accepted / rejected / ambiguous.
- **Profile** — a conditioned access route to an object/relation under stated apparatus, source, and limits. Never "the object itself."
- **Trace** — a consequential indication, held cheaply, before it earns formal relation status.
- **Relation-Object** — a relation once it needs persistent addressability. Type is optional and revisable.
- **Mapping Object** — a versioned, inspectable distant-reading construction. Produces Speculative Indications, not claims.
- **Experiment** — a deliberate change to one encounter condition, stated before execution.
- **Finding** — pressure → operation → encounter → observation → consequence → limit. Never a bare number.
- **Use-Status** — what a record may currently do (descriptive, heuristic, scholarly, blocked, ...).
- **Claim Permission** — how far a proposition may travel (preserve only → argue → block).

Anchor match ≠ object occurrence. Co-incidence ≠ relation. Estimate ≠ census.
See spec Appendix A for the full non-equivalence list — check it before
phrasing any result sentence.
